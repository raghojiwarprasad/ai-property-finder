# Curriculum and content system

## 1. Curriculum structure

Use a directed prerequisite graph of capabilities. A milestone is a learner-facing bundle of capabilities with an outcome and evidence contract. A lesson is one teaching route into a capability; it is not the capability itself. Multiple lessons, examples and assessments may support the same capability.

Separate the canonical concept from personal presentation. The concept of retrieval does not change between a construction professional and a developer. The analogy, detail, required implementation skill and assessment do change.

## 2. Shared foundation spine

| Capability ID | Capability | Illustrative evidence |
| --- | --- | --- |
| F01 | Distinguish AI, machine learning and generative AI | Classify examples and explain a boundary case |
| F02 | Understand generation and uncertainty | Identify unsupported certainty in an output |
| F03 | State a task, context, constraints and output | Improve a task brief against a rubric |
| F04 | Check claims against evidence | Find an unsupported claim using supplied sources |
| F05 | Understand data boundaries and privacy | Choose what to include in an AI task |
| F06 | Understand retrieval and context | Explain what retrieved material can and cannot guarantee |
| F07 | Distinguish a workflow, tool call and agent | Select an appropriate level of autonomy |
| F08 | Evaluate an AI output systematically | Create criteria and apply them to examples |
| F09 | Understand human control and failure handling | Configure an approval or fallback condition |
| F10 | Run a small improvement experiment | Compare approaches with a fixed evaluation set |

These are starting capabilities, not a claim to cover all AI. An experienced learner can check out of relevant foundations while still encountering domain-specific gaps.

## 3. Goal-specific depth

Practical use deepens task framing, evidence checks, data boundaries, repeatable workflows and personal evaluation. Leadership deepens use-case selection, operational fit, decision criteria, economics, accountability and pilot evaluation. Marketing deepens audience evidence, claim verification, creative variation, brand constraints and controlled measurement. Building deepens APIs, structured outputs, retrieval, evaluations, tool permissions, failure handling and observability. Research deepens mathematics, programming, statistical reasoning, optimisation, model evaluation, experiments and critical reading.

These are capability destinations, not fixed courses assigned by occupation. A learner can combine an active goal with optional depth branches, while the planner keeps one clear next activity.

## 4. First release content inventory

Create four complete short milestone bundles plus a research-foundations starter. Each must include teaching, practice, independent checks, feedback and a demonstrable output. A bundle is complete only when its full evidence path is available; a sequence of lesson headings is not complete content.

Bundle A: “Use AI with better judgement.” Output: a reusable task brief plus a checked answer. Bundle B: “Choose and evaluate an AI pilot.” Output: a one-page decision memo with success criteria and failure boundaries. Bundle C: “Create an evidence-based campaign brief.” Output: a sourced brief, two creative variants and an evaluation plan. Bundle D: “Design and test a grounded AI assistant.” Output: a retrieval/evaluation exercise with failure cases; live deployment is not required. Bundle E: “Understand a simple prediction experiment.” Output: a labelled data split, a baseline comparison and a leakage explanation; later mathematics and coding milestones are planned explicitly.

Initial authored inventory target: the ten foundation capabilities, at least three worked examples per applicable context family, and at least four independent item families for each capability used in a release bundle. The number of variants is a product quality target, not an evidence threshold. Avoid cosmetic rewordings being counted as new families.

## 5. Long-range research progression

The research destination requires a staged foundation route. First, AI intuition and basic scientific reasoning. Next, programming fluency, data handling and debugging. Then algebra, functions, vectors, probability, statistics and gradients. Then supervised learning, generalisation, evaluation and optimisation. Then neural networks, representations and model training. Finally, paper reading, reproduction, ablations, uncertainty analysis and original experimental questions.

Do not put all mathematics behind an arbitrary wall before the learner can see AI. Introduce small motivating experiments alongside the foundations, with prerequisite checks before technically demanding work. Supporting foundations must remain accurate and reusable rather than being reduced to metaphors.

There is no promised number of weeks to become a researcher. The first plan can estimate the next published milestone and show the longer route qualitatively. Research readiness requires sustained demonstrated work and expert critique beyond an introductory self-service product.

## 6. Lesson contract

Each lesson stores ID, version, capability and depth, prerequisites, outcome, canonical explanation, common misconceptions, approved source references, context adaptation slots, worked example, independent task families, rubric IDs, hint ladder, transfer task and review prompt. It also records estimated active duration as a range, not a completion promise.

A lesson usually contains an orientation, an intuition bridge, a precise concept statement, an example, a learner action, feedback and a next-step explanation. The sequence can change for learners who already demonstrate the idea. A short conceptual lesson need not contain every medium; use a diagram when the relationship is genuinely easier to see.

## 7. Assessment authoring

Write the desired evidence before the question. Define a correct response, acceptable alternative reasoning, critical errors, partial credit and the assistance boundary. Include at least one plausible wrong answer tied to a real misconception. Avoid trivia about vendor names, unsupported IQ claims or questions that reward memorising the lesson's phrasing.

Independent variants should change the situation, relevant evidence or decision, not only names. Transfer tasks use a different domain. An evaluation set must include strong, weak, ambiguous, copied, partially correct and adversarial answers. Human subject review is required before an assessment can control progression in a pilot.

## 8. Content generation and review workflow

Draft content against the capability schema. Validate prerequisite IDs, factual claims, source links, task/rubric alignment and answer leakage. Review pedagogically and technically. Publish a versioned bundle only after its demonstration path can be completed. Archive older versions without invalidating historical work.

At runtime, the model can adapt examples, pacing and explanatory language inside reviewed boundaries. It may propose a new prerequisite or specialist lesson, but that proposal enters review rather than silently becoming authoritative curriculum. Unsupported advanced questions receive an honest explanation plus available learning prerequisites.

## 9. AI content freshness

Separate durable concepts from changing product details. Durable conceptual material can have a slower review cycle. Vendor interfaces, model capabilities, API examples and pricing require dated references and more frequent checks before publication. Do not freeze a current model leaderboard into the core curriculum.

A retired or corrected lesson remains identifiable in old evidence. If a factual correction materially changes a capability assessment, flag affected records for a follow-up check rather than silently deleting credit. Source failures should not break the entire lesson when the content has a reviewed local explanation.

## 10. Instructional basis and its limits

The design incorporates retrieval practice, spaced review, worked examples, concrete-to-abstract connections and explanatory questions. The IES practice guide supports these broad instructional approaches; see S01. It does not establish that this particular product, schedule or CV-based personalisation improves adult AI learning. That must be evaluated in the product's own pilot.

## 11. Content availability is a product contract

Every goal has coverage metadata: published milestones, preview-only milestones and unsupported areas. An unavailable milestone cannot be selected as today's next task. A model cannot turn an outline into “available” by producing a few paragraphs. The learner should see exactly what they can start now and what remains planned.

# Project instruction template

Copy or merge these instructions into the coding tool's supported project instruction file. Preserve any existing repository rules. This file is a template; it does not change the current environment.

- Read `spec/PRODUCT_DECISIONS.md` before product changes and the relevant PRD before implementation.
- Scope: AI learning and necessary foundations. Exclude career trajectory and Cooper integration.
- Keep context, goal, evidence and preferences distinct. CV facts do not award skill.
- Main navigation: Today, My path, My work. One primary next action.
- Use source-backed personal examples and label fictional scenarios.
- Preserve ambitious goals; vary foundations and support from observed work.
- Models propose language and evaluations; server policy validates and commits state.
- Keep answer keys private, attempts immutable, submissions idempotent and access owner-scoped.
- Label fixtures and incomplete integrations. Never report a mocked provider path as live-tested.
- Use requirement IDs in implementation status and validation reports.
- Do not deploy, spend, contact others or modify unrelated data without the authority required by the project environment.

For Claude Code, merge into a project `CLAUDE.md`; for Cursor, use a project rule or supported `AGENTS.md`. Check current tool documentation before configuring instruction discovery. The staged prompts also work by explicitly asking the tool to read this specification directory.
